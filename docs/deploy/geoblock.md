# Гео-блокировка и блокировка IP

Ограничение доступа по странам и IP-адресам **не реализовано в коде приложения**.
Искать его в [`src/proxy.ts`](../../src/proxy.ts) бесполезно — там только rate-limit
и проверка `Origin`. Блокировка живёт в обратном прокси Traefik, которым управляет
Coolify, и настраивается файлом на сервере.

Этот документ — инструкция к тому файлу и копия его текущего содержимого.

## Где это находится

| Что | Значение |
|---|---|
| Сервер | `185.73.126.199` (домен `energy-tur.ru`) |
| Прокси | Traefik `v3.5.3`, контейнер `coolify-proxy` |
| Плагин | [`github.com/david-garcia-garcia/traefik-geoblock`](https://github.com/david-garcia-garcia/traefik-geoblock) `v1.1.4` |
| Конфиг | `/data/coolify/proxy/dynamic/geoblock-ru.yml` |
| База геоданных | `/traefik/geoblock/IP2LOCATION-LITE-DB1.IPV6.BIN` (IP2Location LITE DB1) |

Плагин подключён к роутерам домена docker-label'ом, который генерирует Coolify:

```
traefik.http.routers.https-0-<id>.middlewares=custom-403-page@file,allow-ru-only@file,gzip
```

`allow-ru-only` — историческое имя, доставшееся от старой настройки с белым списком.
Сейчас оно не отражает смысла, но **переименовывать его нельзя**: имя прописано
в настройках приложения в Coolify UI, и правка только в YAML сломает роутинг
(Traefik начнёт отвечать `500`, потому что middleware из label перестанет существовать).

`custom-403-page` — отдельный middleware, подменяющий страницу отказа. Её отдаёт
служебный nginx-контейнер `q888wk4w0g04c08wkkwwwkk0`, висящий на внутреннем
`sslip.io`-домене. Страница озаглавлена «VPN обнаружен», хотя **никакого детекта VPN
в плагине нет** — текст вводит в заблуждение при диагностике.

## Текущая конфигурация

```yaml
http:
  middlewares:
    allow-ru-only:
      plugin:
        geoblock:
          enabled: true
          defaultAllow: true
          databaseFilePath: /traefik/geoblock/IP2LOCATION-LITE-DB1.IPV6.BIN

          # blockedCountries:
          #   - UA
          #   - CN

          allowPrivate: true

          ipHeaders:
            - x-forwarded-for
            - x-real-ip
            - remoteAddress

          ipHeaderStrategy: CheckFirstNonePrivate

          ignoreVerbs:
            - OPTIONS
            - HEAD
```

`defaultAllow: true` означает «пускаем всех, кроме явно запрещённых».
Чёрный список сейчас пуст, то есть сайт открыт отовсюду.

> До 11.09.2026 здесь стоял белый список (`defaultAllow: false`,
> `allowedCountries: [RU, BY, UA]`), из-за чего сайт был недоступен из всех
> остальных стран. Бэкап той версии лежит рядом: `geoblock-ru.yml.bak`.

## Как заблокировать страну

Открыть `/data/coolify/proxy/dynamic/geoblock-ru.yml` на сервере и вписать
коды стран в формате **ISO 3166-1 alpha-2** (две заглавные буквы):

```yaml
          blockedCountries:
            - UA
            - CN
            - US
```

Сохранить файл — всё. Traefik следит за директорией `dynamic/` и перечитывает
конфиг на лету: перезапускать контейнер не нужно.

## Как заблокировать конкретные IP и подсети

Тем же плагином, отдельными ключами. Значения — CIDR-нотация:

```yaml
          blockedIPBlocks:
            - 45.130.83.135/32      # одиночный адрес — маска /32
            - 203.0.113.0/24        # подсеть целиком
```

Обратная задача — пустить кого-то в обход всех запретов (например, офис или
мониторинг из заблокированной страны):

```yaml
          allowedIPBlocks:
            - 198.51.100.7/32
```

Если списки разрослись, их можно вынести в `.txt`-файлы (по одному CIDR на строку)
и подключить директорией — `allowedIPBlocksDir` и `blockedIPBlocksDir`.

## Порядок применения правил

Плагин проверяет условия сверху вниз и останавливается на первом совпадении:

1. приватные и loopback-адреса → пропуск, если `allowPrivate: true`;
2. `allowedIPBlocks` / `blockedIPBlocks` (выигрывает более узкая маска);
3. определение страны по базе IP2Location;
4. `allowedCountries` / `blockedCountries`;
5. если ничто не совпало — решает `defaultAllow`.

Отсюда практическое следствие: **`allowedIPBlocks` сильнее `blockedCountries`**.
Чтобы закрыть страну, но оставить доступ одному адресу из неё, достаточно добавить
этот адрес в `allowedIPBlocks` — страну при этом трогать не нужно.

Запросы методами `OPTIONS` и `HEAD` не блокируются никогда (`ignoreVerbs`).

## Как проверить, что сработало

Traefik пишет каждое срабатывание в свой лог:

```bash
docker logs --since 5m coolify-proxy 2>&1 | grep -i "blocked request"
```

Строка выглядит так — в ней видно и IP, и определённую страну, и причину:

```
level=INFO msg="blocked request" plugin=allow-ru-only@file ip=51.89.39.61 \
  country=DE host=energy-tur.ru method=GET phase=default_allow path=/...
```

Проверить домен снаружи (код ответа и первые байты тела):

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://energy-tur.ru/
```

`200` — доступ открыт, `403` — сработал блок.

Сразу после сохранения файла в логах появляется
`ERR error="middleware \"allow-ru-only@file\" does not exist"`.
Это **нормально**: Traefik успевает выбросить старый middleware до регистрации нового.
Тревожиться стоит, только если ошибка повторяется с новыми временными метками —
тогда конфиг не распарсился, и роутеры отвечают `500` всем подряд.

## Откат

```bash
cp /data/coolify/proxy/dynamic/geoblock-ru.yml.bak \
   /data/coolify/proxy/dynamic/geoblock-ru.yml
```

Полностью выключить проверку, не трогая роутинг, можно одной строкой —
`enabled: false`. Middleware при этом продолжает существовать, и Coolify-labels
не ломаются.

## Известные ограничения

**Блок обходится подделкой заголовка.** В `ipHeaders` первым стоит `x-forwarded-for`,
а стратегия — `CheckFirstNonePrivate`, то есть берётся первый публичный адрес цепочки.
Клиент волен прислать свой `X-Forwarded-For`, и Traefik лишь допишет реальный адрес
справа — плагин доверится подставленному. Это ровно та же дыра, что описана
в комментарии к [`getClientIp`](../../src/shared/lib/security/client-ip.ts) (HIGH-3).
Если гео-блок должен быть барьером, а не фильтром от случайного трафика, уберите
`x-forwarded-for` из списка, оставив `x-real-ip` и `remoteAddress`: их проставляет
сам прокси, и подделать их клиент не может.

**База неточна.** IP2Location LITE — бесплатная редакция с заметной долей ошибок,
особенно на мобильных операторах и хостинг-подсетях. Часть живых пользователей
неизбежно определится не той страной.

**Гео-блок плохо работает против ботов.** Переборы `/wp-login.php` и `/wp-admin/`,
ради которых обычно и включают такие фильтры, для Next.js-приложения безвредны,
а ценой их отсечения становятся живые посетители и поисковые роботы. Против
перебора уместнее rate-limit, который в приложении уже есть
(см. [`constants.ts`](../../src/shared/lib/security/constants.ts)).

**Конфига нет в репозитории.** Файл существует только на сервере и не попадает
ни в CI, ни в бэкапы кода. При пересоздании сервера его придётся восстанавливать
из этого документа.

## Второй домен

`okryme.ru` (`147.45.219.211`) — **другой сервер**, и к описанному здесь плагину
отношения не имеет. Если он отвечает `503 no available server` и отдаёт сертификат
`CN=TRAEFIK DEFAULT CERT` — значит домен не добавлен в настройки приложения
в Coolify: роутер не создан, сертификат Let's Encrypt не выпущен. Лечится в UI,
а не правкой этого конфига.
